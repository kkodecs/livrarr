# Metadata Insights

Metadata source policy, enrichment merge/status rules, and provider-agnostic metadata behavior.

### 12. **Never use OpenLibrary for foreign language metadata…**

12. **Never use OpenLibrary for foreign language metadata enrichment.** OL IS used for foreign search/discovery (with language filter). Google Books provides the actual foreign-language metadata. See [metadata-sources](domain/metadata-sources.md).

### 16. **Foreign works skip English-centric providers via…**

16. **Foreign works skip English-centric providers via `works.language`.** The applicability rule (server `main.rs` ≈908-919) dispatches only GR/Audnexus/GB/Audible for non-`en` works, and the merge chokepoint drops OL/HC payloads for foreign works (`drop_language_incompatible_providers`). `works.metadata_source` is GONE — dropped by migration 061 (Sprint B REQ-018); an earlier version of this insight wrongly claimed it gated foreign refresh.

### 32. **NotConfigured is terminal but resettable**

32. **NotConfigured is terminal but resettable.** `OutcomeClass::NotConfigured` is in `is_phase2_terminal()` (won't auto-retry), but `reset_not_configured_outcomes()` deletes those rows when config changes. Called from `update_metadata_config`.

### 42. **Author monitor has three independent controls**

42. **Author monitor has three independent controls: `monitored`, `monitor_new_items`, `monitor_since`.** `monitored=true` includes the author in the daily scan. `monitor_new_items=true` auto-adds newly-detected works; `false` creates a notification-only entry (user sees the new work but it's not added to the library). `monitor_since` (optional `DateTime<Utc>`) filters out works whose publish year predates the threshold — only works newer than this date are candidates. These are Author-level fields, distinct from work-level `monitor_ebook`/`monitor_audiobook` (insight 21).

### 76. **`MergeOutput.work_update` is a last-known-good ECHO**

76. **`MergeOutput.work_update` is a last-known-good ECHO — presence is NOT a change signal — and `ApplyMergeOutcome::NoChange`/`Deferred` have ZERO producers** (`SqliteDb::apply_enrichment_merge` returns only `Applied`/`Superseded`). Found at work-history Stage 5 (2026-07-19): the design assumed presence-derived `changed` meant "fields changed"; in fact it was true on every completed merge with any eligible provider (`merge_engine.rs` emits the echo unless providers were attempted AND all excluded). Truthful change detection is `content_changed` (`livrarr-enrichment/src/lib.rs`): a pre/post work-row diff excluding the bookkeeping the apply always stamps (`enrichment_status`, `enrichment_source`, `enriched_at`), computed at both `enrich_work` completion arms; `Work` derives `PartialEq` for it. Consequence: `EnrichmentResult.changed` is truthful, so materialize's change gate (tag rewrite) now skips genuinely no-op passes — before this it re-tagged on every completed pass, and the work-history `enriched` event would have said `changed:true` forever.
