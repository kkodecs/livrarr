⚠ Issue #97 — manual import is still OpenLibrary-only

The work-creation-consistency feature wired the multi-provider resolver into the Add Work path (#1/#2) and the bulk/monitor seeds (#4/#5/#6). The manual import path (#3) — the literal subject of #97 — was never connected: its search (search_ol_works) queries only OpenLibrary, and its add builds identity straight from the OL row with candidate_id: None (no resolve).

Fix: route manual import's search + pick through the same resolver discovery the Add Work path now uses, so HC/GR/GB candidates surface (with a gr_key) and the work can be created — "manual import will create if a gr_key is found."
